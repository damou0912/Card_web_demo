# 抽卡 Demo

本地离线原型，使用免费测试额度。不接充值、支付、游戏账号或线上数据库，卡牌与碎片不进入组卡／对局。Unity 与浏览器共用 `Assets/Scripts/Core/GachaDemo.cs`，没有第二套 JavaScript 抽卡算法。

## 试玩

- 无需 Unity：双击工程根目录 `Start-Gacha-Demo.cmd`，启动后用浏览器打开 `http://127.0.0.1:5186/`。需要 .NET 8 SDK，无第三方依赖。保持命令窗口开启，Ctrl+C 停止。
- Unity：`Card Demo → Tools → Gacha Demo → Open Demo Scene`，打开 `Assets/Scenes/GachaDemo.unity` 后 Play。页面按竖屏设计，可滚动。
- 已有 Main 对局：顶部“招募 Demo”按钮打开独立覆盖页。打开期间暂停本地演示对局与倒计时，关闭后恢复，不丢失对局。
- 点击任意卡牌看完整技能；卡牌下方只显示完整卡数量（拥有 0／1 张），不逐卡显示碎片。顶部显示完整卡总数和碎片总数；重复卡仍自动转为碎片，不累积完整卡数量。首次集齐即停止继续抽取，需确认重置才能再测试。
- 本页新增“兑换卡牌”候选区及页内跳转，列出未拥有的卡，兑换按钮明确禁用并标注“兑换价格待确认”。本轮仅完成布局，不存在兑换 API，也未改动同名碎片绑定、概率或存档；是否改为通用碎片、兑换价格与对平均集齐成本的影响，待用户确认后实现。

未启动 Unity 验证渲染；当前已实际验证的是纯 C# 核心、浏览器页面和本地 HTTP 服务。不要把本服务直接发布到 Railway 作为正式账号／支付服务。

## 抽卡演出

- 墨色聚光／“将”字入场 → 五张卡背展开 → 当前卡背透出品质色 → 依次翻牌 → 入藏及碎片提示。全普通五连约 3.9 秒；高品质有更长停留，保底补发在正常五张后继续揭晓。
- 品质视觉：普通白、稀有蓝、史诗紫、传说橙、特殊青绿。卡面及结果页使用大品质标签、完整彩色边框和浅色底，结果页另列本次各品质数量；特殊是独立类别，不是高于传说的等级。
- 稀有翻开后停留约 0.65 秒，特殊约 0.75 秒；史诗蓄光约 0.38 秒＋紫色中央特写约 1.5 秒，传说蓄光约 0.7 秒＋橙色中央特写约 2.4 秒。重复卡和保底卡不会因奖励类型而缩短品质演出。每张切换时清除上一张的品质主题与特写，避免橙卡标题留在普通卡上。
- 浏览器增加“预览五种品质 · 不抽卡”，按白、蓝、青绿、紫、橙依次展示资料库样卡，全程标注预览，不发送抽卡请求、不写存档、不获得样卡。预览与正式抽取共用演出组件；演出和结果页仍只读真实卡牌品质，不修改势力、技能或随机概率。
- 浏览器和 Unity 都有“跳过动画”及“重播本次”，键盘 Escape 也可跳过。重播只读最后一次已保存结果，不发起抽卡、不扣额度、不修改碎片。
- 浏览器跟随系统“减少动态效果”设置直接展示结果。Unity 本版提供手动跳过，未接入各平台系统的减少动画设置。
- 演出期间禁止再次抽取／重置。先完成存档再揭晓，跳过、关闭页面或动画异常不会撤销已保存奖励；刷新后可恢复结果。跳过请求等待阶段不取消或重复发送抽卡请求。
- 窄屏多行展示；保底补发可超过五张，卡牌区会滚动到正在揭晓的卡，跳过按钮保留在卡牌区外。没有改动概率、价格、保底或存档格式。
- 当前是代码制作的入场、翻牌和品质光效，没有正式立绘、粒子素材、配音或抽卡音效。

- 初始 500 测试元，每次 20 测试元，五张独立抽取，允许同次重复。先选择品质，再在该品质中等概率选卡，避免把 20% 错算成每张稀有卡的概率。
- 样例池为蜀势力备选卡：李恢、张任、陈到、刘封、刘琦、法正、蒋琬、张飞、刘备、七星灯。ID 从卡牌资料读取，品质须与资料相符。
- 第 15 / 20 / 25 次五连（300 / 400 / 500 测试元）结算后，最低收集 8 / 9 / 10 张。正常五张不被替换，缺卡按原单卡权重的相对比例额外补发，补到目标为止。因此保底轮可能显示超过五张奖励。
- 第 25 次必补齐所有缺卡，包括橙卡。橙卡没有 200 元的最低门槛，首次五连也可能获得。此前最新确认口径为最高 500 元。
- 每张卡首次获得入藏，其后重复转换为对应卡牌的碎片。没有通用兑换池；仅预留升级用途，不开放尚未确定消耗规则的升级按钮。
- 350 元是大量首次集齐的平均成本目标，不是每位玩家固定花费。固定种子 100000 次模拟：均价 **349.68**，首次橙卡均价 **318.17**，最大 **500**，37.76% 在最终保底轮集齐。

修改概率或里程碑后必须重新模拟，不能继续沿用上述均价。金额和阈值在本 Demo UI 中按已确认方案展示；改变价格体系时也应同步界面说明和测试。

## 保存与隔离

- 浏览器：`Artifacts/GachaDemo/browser-save.json`，属于本机测试数据，不随 Git 提交。同一服务的多个页面共用此存档。只监听 `127.0.0.1`，只提供页面与三个 API，不提供工程目录浏览。
- Unity：`Application.persistentDataPath/gacha-demo-v1.json`。和浏览器存档独立，没有自动互通。
- 每次抽取先生成新状态并完成存档，成功后才更新界面。写入失败保留旧额度。浏览器额外校验来源、短期进程令牌和存档 revision，阻止重复提交／旧页面重复扣测试额度；不自动重试抽卡请求。
- 单个本地服务持有存档锁。第二进程不可同时写同一存档。损坏存档阻止继续抽取；确认重置时保留损坏文件副本。正常重置会清空当前 Demo 进度，请先确认。
- 本地存档可被用户编辑，不属于防作弊设计。正式付费版仍需服务端权威随机数、登录身份、数据库事务、请求幂等、支付核验和合规审查。当前无真实交易。
