# 浏览器卡牌工坊

独立的节点式卡牌制作工具，不需要启动 Unity，不改变 Web 正式卡表、账号、玩家库存或服务器数据。无第三方前端依赖；安装 Node.js 18+ 即可离线启动。

## 现有卡牌预存

初次打开自带 **90 张正式卡牌、135 段技能流程**，三国各 30 张，包括 60 张基础卡和 30 张额外卡。不包含临时守军、AI 特性或 Unity 演示卡，它们不是正式可组卡库。可按卡名、原始 ID、技能名搜索，也可筛选三国势力。

- **13 张已映射到工坊节点**：王平、周仓、张苞、马岱、糜芳、黄忠、曹休、夏侯恩、于禁、王异、韩当、陈武、徐盛。支持改参数、流程预演、单独导出 Unity 制作库。映射的是触发 / 目标 / 数值语义，并不表示完整 Web 环境下所有规则和其他卡牌互动均已移植。
- **77 张参考卡**：原技能的事件、条件分支、处理顺序和被动限制按当前 Web 实现逐项预存。每个钩子一个流程页签；多事件技能不会被合并成一个错误的入场技能。可以拖动、缩放、选择节点阅读完整说明，也可以逐步浏览；到达条件时需手动选择假设满足 / 不满足，工具不计算真实战场。
- 参考图为保留原规则，不能改连线或删除节点。没有把“技能攻击”冒充“摧毁”，也没有把替身保护冒充一次护盾。参考卡不可导出为可运行 Unity 卡牌；整库使用「保存工程」保留全部内容；可运行卡牌使用「导出当前卡」单独导出。
- 保留原始卡牌 ID、原技能全文、来源脚本和差异备注。工坊副本的配置 ID 使用 `workshop_web_原ID`，避免覆盖正式卡牌；卡牌势力字段不变。
- 检测到旧草稿时，先把原始 JSON 备份在 `card-workshop.project.v1.before-production-presets`，再补齐缺失的预存卡；按来源 ID 去重，不覆盖已经修改、改名或改 ID 的原卡副本。已有卡组引用不变。更新的预存包也不会静默覆盖已编辑卡牌；可显式使用「补齐缺失预存卡」。普通文件导入仍是整库替换，不自动混入预存卡。
- 已记录若干说明与代码差异。例如甄姬说明包含防止战力减少，但当前脚本缺少引擎读取的 `preventReduction` 标记；本次仅预存并标注，不修改正式游戏规则。

数据源为当前实际加载的 `card-info.js`、`replacement-cards.js`，流程核对 `shu-card-effects.js`、`wei-card-effects.js`、`wu-card-effects.js` 与 `core-v2.js`。没有从旧 Unity 快照或过期表格推断。生成器检查全部卡 ID、执行钩子和 flags 是否被覆盖。

```sh
npm run generate:workshop-presets
node card-workshop/build-presets.cjs --check
```

维护 `preset-definitions.cjs` 后重新生成 `presets.js`。卡表或正式规则变化后，测试会提示需要重新核对 / 生成预存包。

## 打开

仓库根目录双击 `Start-Card-Workshop.cmd`，浏览器访问 `http://127.0.0.1:5190/`。或者：

```sh
npm run workshop
```

端口占用时可运行 `node card-workshop/server.cjs 5191`，再访问相应端口。关闭服务终端停止运行。本地服务仅绑定 `127.0.0.1`，仅开放编辑器五个静态文件，没有写入 API；不要用它作为公网生产服务。

## 制作流程

1. 左侧编辑卡牌资料。ID 必须以 `workshop_` 开头；势力和品质仅为卡牌数据，不会自动改变技能。
2. 每张卡可保存 0～8 个技能；点击技能页签切换。
3. 拖动节点标题调整位置，拖动画布空白处平移；使用 `＋ / −` 缩放或「适应画布」。
4. 点击左侧效果按钮，在完整流程末尾自动插入效果。如果原流程已断开，则创建未连接节点。
5. 点击右侧出口后点击下一个节点左侧入口，也可以直接拖动端口连线。新的连接替换同一出口的旧连接，以及目标的旧入口（结束节点可有两个入口）。双击连线或在效果参数里「断开出口」可删除连线。
6. 可执行技能只支持 `触发 → 条件 → 1～8 个顺序效果 → 结束`，条件不满足直接结束。连接不完整、循环、不合法的数值会阻止导出；编辑期间允许保存未连接草稿。删除效果会尽可能连接前后节点。原卡参考流程可展示复杂分支，但不会因此自动获得执行能力。
7. 「流程预演」用输入的手牌数、占领数、相邻敌方条件检查路径，逐步高亮。它不模拟真实战斗，不检查目标存活、护盾、连锁或胜负。
8. `Ctrl/Cmd + Z` 撤销；`Ctrl/Cmd + Shift + Z` 重做。节点选中后按 Delete 删除效果。删除卡牌、技能需确认，可以撤销。

## 文件与 Unity 对接

- **保存工程**：下载 `card-workshop-project.json`，包含图的位置、节点与连线、卡牌及导入时的测试卡组。可重新导入继续编辑。
- **导出 Unity 整库**：校验整库后下载 `workshop-library.json`，保持现有 `WorkshopLibrary` schemaVersion 1。技能描述从效果步骤自动生成，连线顺序决定 `steps` 顺序，而不是节点在画布上的位置。含参考卡时禁止导出整库，不会静默跳过参考卡。
- **导出当前卡**：只导出当前一张可执行卡牌，`decks` 为空；参考卡禁止此操作。Unity 导入仍是整库替换草稿，导入前先备份 / 合并，不要以为是追加一张卡。
- **导入 JSON**：支持浏览器工程和 Unity 工坊制作库（最多 200 张 / 文件 2 MB）。替换当前制作库前确认，支持撤销；Unity 的原有测试卡组保持不变，改卡牌 ID 会同步更新其引用。仍被测试卡组引用的卡牌不能删除。新增示例没有测试卡组，请在 Unity 工坊中配置后再测试。
- **Unity 入口**：`Card Demo → Tools → Card And Skill Workshop → 导入 JSON`。这是整库导入，不是自动合并；先导出备份现有库，再导入和保存。纯规则兼容检查不等于打开了 Unity 编辑器。
- 浏览器草稿仅在同一浏览器、同一地址 / 端口下自动保存，存储失败时有提示。换设备请使用工程文件，定期备份。另一标签页改动同一个草稿时暂停覆盖。发现无法解析的旧草稿时保留它，不自动清空；当前工作仍可下载保存工程。

### 当前边界

触发、条件、效果枚举及数值校验来自 `UnityCard_demo/Assets/Scripts/Core/WorkshopModels.cs`。支持加减战力、赋予一次护盾、所属玩家抽牌、尝试摧毁、当前行动阶段加行动。每个效果独立选目标；两次随机选择不锁定同一张卡。护盾不叠加；摧毁可能被护盾阻挡；临时战力在当前全局回合结束清除。实际结果仍由 C# 引擎负责。

未接入正式 Web 卡牌的 JavaScript 技能；不是行为树 AI 编辑器。未实现自由多条件分支、循环、跨步骤目标引用、Excel / Lua 技能导出、美术资源编辑、共享账户、云端同步或正式发布。不会自动覆盖 `Card Basics.xlsx` 或正式技能表现表。

## 验证

```sh
npm run test:workshop
dotnet run --project card-workshop/compat/WorkshopCompat.csproj --configuration Release -- UnityCard_demo/Assets/Resources/Data/workshop-library.json
```

`compat` 直接引用现有 C# 核心，验证浏览器往返导出与 Unity 工坊校验器兼容，不修改卡库。导出自己的 JSON 后也可以将路径作为参数传入验证。

若本机已安装 Playwright，运行 `node card-workshop/browser.test.cjs` 做浏览器回归；可设置 `WORKSHOP_PLAYWRIGHT` 为现有 Playwright 包的绝对路径，不自动安装依赖。
可设置 `WORKSHOP_BROWSER` 指向本机 Chrome / Edge 可执行文件，用独立临时配置目录测试；不会使用日常浏览器的账号或历史。
