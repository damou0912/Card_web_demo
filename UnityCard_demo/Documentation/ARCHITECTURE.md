# 架构与下一阶段

## 目录

```text
UnityCard_demo/
  Assets/
    Scenes/Main.unity             启动场景，Play 后生成 UI
    Scripts/Core/                 不引用 UnityEngine 的纯 C# 演示规则
    Scripts/Runtime/              uGUI 展示、交互、时钟、AI 调度
    Editor/                       配置窗口、校验和构建菜单
    Resources/Config/             JSON 参数
    Resources/Data/               演示卡 + 正式资料快照
    Resources/Fonts/              自带中文字库和许可
    Tests/Shared/                 Unity 与 .NET 共用的规则检查
    Tests/EditMode/               Unity Test Runner 入口
  Packages/                       固定依赖
  ProjectSettings/                Unity 版本、输入、场景列表、文本序列化
  Tools/                          安装导航、启动／构建、数据导入、独立测试
  Documentation/                  架构、验收与字体来源
```

## 当前规则与正式游戏的区别

工具版新增：独立制作库、表单式技能组合器、测试卡组和战斗实验室，详见 `AUTHORING_TOOLS.md`。
`SkillRuntime` 与旧演示规则同属纯 C# 核心；新技能按结构化触发／条件／步骤执行，不解析自然语言。
制作库是显式启用的开发数据，未替换正式网页资料或宣称完成正式技能迁移。

这个工程的目标是可以单独导入、配置和继续开发，不是宣称完成全部网页移植。

演示沿用一部分基础交互：固定玩家视角、占领己方卡所在格、轮流行动、守军、手牌／牌库、回合数和认输。五张演示卡使用独立 `demo_` ID，不能把演示效果映射为正式卡牌技能。

尚未实现的正式机制包含破坏格、完整正式技能触发顺序、重新放置、正式品质配额与组卡、混沌、PVE 挑战、账号、房间与观战、联网重连、抽卡和支付。工具版支持临时战力和每操作 10 次技能安全上限，但不等同于完整正式结算。默认仅玩家对 AI，没有本地双人 1v1；实验室可手动控制双方，仅用于开发测试。

`GameEngine` 是便于本地测试的可变状态模型，不应把客户端状态当成可信输入直接用于正式联网。生产接口需做身份、顺序、合法性、服务端随机数和超时验证。

## 推荐的完整迁移顺序

1. 在一台干净电脑安装固定 Unity 版本，完成导入、Play、EditMode 测试和 Windows 构建；确认后提交 Unity 生成的设置差异。
2. 按选用的微信转换 SDK 文档验证 Unity 版本支持。当前固定版本已验证在 Unity 官方下载服务存在，但没有验证微信 SDK 兼容矩阵；必要时在独立分支升级。
3. 在微信真机验证 Canvas/uGUI、字体、包体、触控、加载和切后台；当前 8.3 MB 完整中文字体优先保证缺字问题，发布前再做合法字体子集化与分包优化。
4. 决定正式规则的唯一权威实现。优先迁出现有网页房主结算，放到服务器；Unity 提交命令，展示服务端结果与流程事件，避免维护两套不同规则。
5. 逐个接入正式卡牌，使用正式卡牌 ID 分离数据与效果代码，添加技能、胜负和连锁回归测试；再迁移组卡、挑战和 AI。
6. 接入微信登录后的自有会话、正式数据库、房间、观战、断线恢复与服务器回合截止时间。
7. 最后才接入付费抽卡和支付；密钥、余额、抽取随机数和事务必须在服务端。

## 环境与安全

- `Setup-Windows.ps1` 默认不安装任何东西。显式开关才会执行 winget 安装或打开 Unity。
- 不提供破解、自动绕过许可、关闭安全软件或修改全局 PowerShell 策略的工具。
- 不设置硬编码的本机项目路径；构建脚本根据自身位置定位工程。
- 客户端 JSON 不允许保存服务端密钥。AppID 不是 AppSecret。
- 只提交源码和合法资源；编辑器、下载缓存和构建产物不上传。
- 不对用户的现有网页版源文件做改动；新增 GitHub 工作流只针对这个工程的路径触发。
